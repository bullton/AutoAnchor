# 口播工坊 · 跨机器移植问题汇总

> 记录时间：2026-11-22
> 机器：Apple M1 / 8 核 / 16GB / 可用磁盘 43.8GB（darwin-arm64）
> 来源：项目在开发机完成后，整体搬到这台 Mac 上实测。
> 目的：交给开发机统一修复。

---

## 0. 一句话结论

**主链路能跑通并出片（1080×1920 / 49.87s），但三条关键能力在这台机器上不可用或会误导人：**

1. **改文案不生效** —— 分镜哈希与内容脱节，系统判定「可复用」，实际跑的是项目自带的运维样例文案。这是最严重的问题。
2. **语音克隆完全不可用** —— 参考音频上传成功、配置也写进去了，但没有任何一条能真正执行克隆的链路。
3. **默认配音方案在本机不存在** —— setup 默认给 `voicestudio`，而 `vendor/VoiceStudio` 后端在本机根本没有。

## 2. P0 · 改了文案，成片还是旧的（最严重）

### 现象

用户在界面把文案改成测试文案「哈喽大家好！今天来做个小测试……」，点生成后，成片仍然是项目自带的 8 幕运维内容（「终端运维自动化到底省了多少钱」），配音也是那条运维音频。

### 证据链

**文件层面：两个文案源并存**

```
input/test-data.txt   691B   15:58   运维样例文案（8 句）
input/script.txt      148B   19:11   用户改的测试文案
```

`server.mjs:32` 只认 `input/script.txt`：

```js
const SCRIPT_FILE = path.join(PIPELINE_ROOT, "input", "script.txt");
```

但当前生效的分镜来自另一个文件：

```
output/props.json
  meta.source      = "test-data.txt"          ← 源自运维样例
  meta.scriptHash  = "f193a69433f25ca4"       ← 却是 script.txt(测试文案) 的哈希
  scenes[0].title  = "终端运维自动化到底省了多少钱"
```

实测哈希比对：

| 对象 | sha1[0:16] |
|---|---|
| 当前 `input/script.txt`（测试文案） | `f193a69433f25ca4` |
| `output/props.json` 的 `meta.scriptHash` | `f193a69433f25ca4` ← **一致** |
| `output/props.json` 的 scenes 实际内容 | 运维文案，正确哈希应为 `6d5074da77ebef37` |
| `output/slides.json` 的 `meta.scriptHash` | `6d5074da77ebef37` |

**于是 `storyboardStatus()` 判定 `stale = false`。**

### 后果

`output/runs/20261122-191127/job.json`：

```json
"reusedStages": [1, 2]
阶段1 生成分镜  status=done reused=true  note=复用上次分镜
阶段2 合成配音  status=done reused=true  note=复用上次配音
```

第 1、2 阶段被整体跳过，配音沿用 18:04 的旧 `voice.wav`，分镜沿用 17:57 的旧 8 幕，只有 04/05 重跑了一遍。用户看到的就是「改了文案毫无反应」。

### 根因（两处叠加）

1. **`server.mjs:938 storyboardStatus()` 过度信任 `meta.scriptHash`**

```js
if (metaHash) {
  stale = metaHash !== hash;   // 只比哈希，不看 scenes 内容
}
```

哈希一旦被同步成新值，就永久「自证清白」，之后无论怎么改文案都不再判定过期。

2. **存在「只刷新 meta 哈希、不重生成 scenes」的写回路径**

`props.json` 的 mtime 是 19:31，而 `scenes` 的 `createdAt` 是 17:57。说明 19:31 有人重写了 meta（把 scriptHash 刷成新文案的值）却没动 scenes。可疑入口：
- 手动改 props 后写回（本次为去掉数字人改 `layout.mode` 时触发过）
- `pipeline/01b_preview_props.mjs` 预览同步
- `server.mjs` 保存文案时的预生成流程

需要开发机确认是哪一条，并**禁止**在没有重新生成分镜的情况下更新 `meta.scriptHash`。

### 建议修法

- `storyboardStatus()` 增加**内容级校验**：把 `scenes` 的 `speech` 拼接后与当前文案做长度/相似度比对，不能只信 `meta.scriptHash`。
- `meta.scriptHash` 与 `scenes` 必须**原子写入**，任何只改 meta 的路径直接报错。
- `input/test-data.txt` 与 `input/script.txt` 双源要收敛：要么 UI 明确展示「当前使用哪个文案文件」，要么统一成单源。
- 复用配音时，`findReusableVoice()` 除了哈希，还应校验 `voice.wav` 的 mtime 晚于文案 mtime。

## 3. P0 · 语音克隆完全不可用

### 现象

界面上传了参考音频，看着像是配好了，但成片用的是 Edge-TTS 的固定音色（`zh-CN-XiaoxiaoNeural`），根本不是本人的声音。

### 实测

参考音频**确实上传成功了**：

```
assets/voice-ref/voice-20261122-175116-624.wav   320KB   17:51
```

`config/private.json` 里各方案的指向也都正确：

```json
"voicestudio": { "refWav": "assets/voice-ref/voice-20261122-175116-624.wav", "refText": "" },
"cosyvoice":   { "refWav": "...", "refText": "" },
"local3":      { "refWav": "...", "refText": "" },
"indextts":    { "promptWav": "..." },
"kaggle":      { "promptWav": "..." }
```

但**五个能克隆的方案，没有一个具备执行条件**：

| 方案 | 缺什么 |
|---|---|
| voicestudio | `vendor/VoiceStudio` 后端不存在（仓库不包含） |
| cosyvoice | `models/CosyVoice2-0.5B` 权重未下载 |
| local3 | `models/Fun-CosyVoice3-0.5B` 权重未下载 |
| indextts | IndexTTS 本地部署未安装 |
| kaggle | 依赖云端排队，见 §5.3 |

唯一能跑的 `edge` 是微软在线 TTS，**架构上就不支持克隆**。

另外 `refText` 全为空 —— 即使装上后端，缺朗读文本也会明显影响克隆稳定性。

### 建议修法

- UI 在「已上传音色」状态下，必须明确提示「**当前方案 edge 不支持克隆，你的音色不会被使用**」，而不是让用户以为配好了。
- `doctor.mjs` 当前只显示「样本声音 使用引擎内置音色」，未提示「已有克隆音色但当前方案用不上」。应改为显式冲突提示。
- setup 里 `refText` 允许留空，但应在留空时警告（影响克隆质量）。

## 4. P0 · 默认配音方案指向不存在的组件

`setup.mjs:95`：

```js
const provider = await ask("默认配音方案", "voicestudio", "voicestudio / local3 / indextts / kaggle / edge");
```

`voicestudio` 需要 `vendor/VoiceStudio` 后端，而该目录**不在仓库里**（`.gitignore` 忽略了 `vendor/`）。新机器跑完 setup 直接回车，得到的就是一个**开箱即不可用**的配置。

后续 `setup.mjs:100` 还有连带问题：

```js
if (provider !== "edge") {
  // 才问样本声音
}
```

选了默认的 voicestudio 但没放音频时，只打印一句「提示：没有找到样本声音」就继续写配置，**不阻断、不回退**。

### 建议修法

- 默认值应来自探测结果：探测到什么可用方案就默认什么，一个都没有时强制选 `edge` 并说明原因。
- setup 结束前跑一次**可用性自检**，方案不可用就明确报错并要求重选。

## 5. P1 · 功能与稳定性问题

### 5.1 三处观感缺陷（已定位到行号）

| # | 现象 | 位置 | 根因 |
|---|---|---|---|
| 1 | 末幕引用块「深色字压深色底」几乎不可见 | `remotion/src/narrated/layouts.tsx:692-709` | 胶囊底 `background: ${palette.accent}1F`、文字 `color: palette.accent`，**同色系**。实测底 `(56,50,43)` / 字 `(227,162,69)` |
| 2 | 第 4 幕标题重复出现两次 | `layouts.tsx` Compare `L437`+`L439`；同样问题在 Abstract `L582`+`L585`、Bars `L392`+`L394` | `TitleBar` 已渲染 `scene.title`，布局内部又用 `Headline` 渲染同一字符串 |
| 3 | 多幕照片被压得过暗 | `remotion/src/narrated/parts.tsx:208 / 278 / 206` | ① L208 渐变末尾 `${palette.bg}` **漏写 alpha**，92% 位置完全不透明；② L278 额外压一层 `Math.min(0.5, dim*0.7)`；③ L206 hero 渐变两端 80%/91% 过重 |

补充：顶部 `Masthead.tsx` 的 140px 报头（「今天用一组 / 真实数据」）**8 幕全程常驻**，占顶部约 300px，与幕标题、布局内标题构成三套文字层级，是「观感重复」的另一来源。

建议：① 改反色实心胶囊或白字+描边；② 三个布局的 `TitleBar` 只留 kicker；③ 修 L208 的 alpha、`dim` 降到 0.18 左右、`brightness` 提到 1.12。

### 5.2 FFmpeg / FFprobe 版本混用

```
FFmpeg    6.0        ← vendor/ffmpeg/ffmpeg（npm ffmpeg-static 提供）
FFprobe   8.1.1      ← 系统 Homebrew
```

原因：Homebrew 的 ffmpeg 8.1 **编译时未带 libass/freetype**，没有 `subtitles` / `ass` / `drawtext` 滤镜，`05_compose` 烧字幕必失败。临时解法是换成 `ffmpeg-static` 的 6.0 静态版（带 libass）。

遗留风险：**探测用 8.1.1、合成用 6.0**，两边对容器/流参数判断可能不一致。建议成对统一，或在 preflight 里显式校验 `ffmpeg -filters | grep subtitles`。

### 5.3 Kaggle 排队不可预期

`kaggle kernels push` 是批量任务，进 FIFO 队列，实测长时间无响应；而浏览器 JupyterLab 的交互式 session 秒开。

- 参数已核对 8 项无误（`machineShape=NvidiaTeslaT4`、`enableGpu`/`enableInternet=true`、数据集挂载正常）。
- 取消方式只有用 `--no-run` 推新版本顶掉旧版本，**不能删单个版本**。
- 事后配额仍为 1.76h 未消耗，说明是排队而非执行。
- 数字人链路因此不可用时，应能一键降级到「无数字人」快速出片，目前需要手工改 `props` 和 `pipeline/layout.json`。

### 5.4 Remotion 首次渲染超时

首次渲染会先下载 Headless Shell，随后内建浏览器 30s 超时导致失败；**重跑一次即正常**（1496 帧约 2 分钟）。属于冷启动问题，建议在 `04_render` 里做一次预热重试。

### 5.5 `pipeline/tts/config.json` 被界面整份覆写

`server.mjs:1660` 的 `writeJson(TTS_CONFIG, publicTts)` 会把整份配置重写：

- 原本的空占位字段（`refWav` / `refText` / `promptWav` / `profileId`）被删除
- `provider` 从 `voicestudio` 变成 `edge`
- 文件末尾换行丢失

结果仓库里的默认配置被运行时状态污染，git diff 噪音大。建议改为**深合并写回**，只更新用户实际改动的字段。

### 5.6 去掉数字人需要手工改三处

字幕安全距由 `pipeline/layout.json` 的 `mode` 决定（有数字人 `MarginV=811`，无数字人 `240`）。切换成片形态时必须手工改 `mode` 再重跑 `03_timeline`，否则字幕位置错乱。建议做成一个显式开关。

### 5.7 AI 分镜读不到宿主模型

已确认 WorkBuddy 不暴露 OpenAI 兼容端点（18488 的 `/v1/models` 返回 404），也没有 CLI 二进制。当前采用「会话模型产出计划文件 → `--plan` 回灌」的折中方案：

- `pipeline/01_storyboard.mjs --plan <file>`：走 `validatePlan`，不联网
- `--prompt-out`：导出 prompt 供外部模型使用
- 自动发现 `output/plan.agent.json`，带 `scriptHash` 校验

但这是**本机手工补的**，不是产品化能力。界面上的 AI 分镜仍然只支持 OpenAI 兼容端点。

## 6. P1 · 部署交互不足（重点）

### 6.1 一次性连问 12 个路径，缺少分组与解释

`setup.mjs:82-94` 连续追问：

```
Python 路径 / FFmpeg / FFprobe / Chrome（可选）/ 模型根目录 / 依赖根目录 /
VoiceStudio 目录 / IndexTTS 目录（可留空）/ Kaggle Python / Kaggle CLI /
参考音色目录
```

问题：

- 没有任何一项说明「这是什么、不填会怎样、可以跳过吗」
- 除 Chrome / IndexTTS 外都给了默认值，用户实际只会一路回车，**等于没配**
- 路径类问题应在探测失败时才问，探到了就直接用不打扰

### 6.2 不接入硬件预检

`scripts/preflight.mjs` 已经能算出「本机能不能跑某模型 / 要下多少 GB」，但 **setup 完全没调用它**。用户在 setup 阶段看不到：

- 我这台机器适合哪个方案
- 要占多少磁盘 / 内存
- 下载体积多大

结果是先配完、再发现跑不了（§4 的默认 voicestudio 就是这么来的）。

### 6.3 没有验证闭环

setup 写完 `config/private.json` 就结束了，**不跑自检、不启动服务、不验证方案可用性**。`doctor.mjs` 存在但要用户自己去 `npm run doctor`。

### 6.4 `--yes` 是静默的危险模式

`setup.mjs:74` 的 `yes` 模式下所有问题直接返回 fallback，等于**不询问、不验证**生成一套配置，并写入 `setupCompleted: true`。看起来配置成功，实际可能全套不可用。

### 6.5 Kaggle 凭据方式与实际 CLI 不一致

setup 只问「用户名 + API Key」（`setup.mjs:135-136`），但 CLI 2.x 走的是 `~/.kaggle/access_token`（ACCESS_TOKEN 模式），需要 `kaggle auth login`。两者不互通，实际是手工另配的 token 才打通。setup 应直接引导 token 方式，并说明配额查看方法。

### 6.6 外部依赖缺少统一引导

用户明确要求「引用外部模块要引导配置和安装；本地模型要先检测适配再提示下载；不配置就纯走第三方」。

现状：

- Kaggle 有单独的 `npm run setup:kaggle`，但 setup 不提示
- 语音克隆后端（VoiceStudio）完全没有安装引导，只是缺目录然后报错
- 本地模型有 `preflight` 但不自动衔接下载
- 三者散落在不同脚本，没有一个「依赖总览」页

### 6.7 界面方案卡片不给下一步

未就绪的方案只是置灰 + 一句原因（本轮已补），但**没有可点击的修复动作**（装什么、跑哪条命令、多少体积）。用户看到「未下载 CosyVoice2 权重」后仍不知道该做什么。

## 7. 跨机器移植的整体评估

### 做得好的地方

`.gitignore` 覆盖很完整，私有状态不会进仓库：

```
config/private.json   models/   vendor/   output/
assets/voice-ref/*    assets/avatar/*   assets/photos/*
input/script.txt      pipeline/ui.json  pipeline/layout.json ...
```

仓库本身是干净的，拉下来不会有别人的路径和成片。

### 代价：所有本地状态都要重建

搬机器后以下全部为空，且没有一键重建入口：

| 需要重建 | 现状 |
|---|---|
| `config/private.json` | 需手动跑 setup（且默认值不可用，见 §4） |
| `vendor/ffmpeg` | npm 装 `ffmpeg-static` 再手工拷路径，无脚本 |
| `pipeline/tts/.venv-kaggle` | 有 `npm run setup:kaggle`，但需自己发现 |
| `assets/voice-ref/*` | 音色不随仓库走，需重传 |
| `assets/photos`, `assets/avatar` | 素材需重传 |
| `models/` | 权重需重下（4.86~5.49GB） |
| Python 依赖 | `edge-tts` / `numpy` / `soundfile` 需手工装，无 requirements |

另外 `config/private.json` 里全是本机绝对路径：

```
/Users/bullton/.workbuddy/binaries/python/versions/3.13.12/bin/python
/Users/bullton/Documents/Coding/autoanchor/vendor/ffmpeg/ffmpeg
...
```

虽然是 gitignore 的私有文件，但**每次换机都要重新生成**，说明这套「路径发现」逻辑还不够自动。

### 建议

- 提供一个 `npm run bootstrap`：串起 preflight → 依赖安装 → setup → doctor，一条命令走完并逐步汇报。
- 补 `requirements.txt`（至少 edge-tts / numpy / soundfile）。
- Python / FFmpeg 的发现逻辑优先用 `which` / `PATH`，找不到再问，不要一上来就让人填绝对路径。
